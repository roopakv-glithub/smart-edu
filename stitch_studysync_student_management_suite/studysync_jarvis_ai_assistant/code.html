Can you summarize the difference between synchronized blocks and ReentrantLock in Java?

Java Concurrency Summary CS204 Notes Indexed

Both mechanisms guarantee mutual exclusion and thread visibility, but differ substantially in control granularity and syntax flexibility:

lock 1. Flexibility & Scope

synchronized is strictly block-structured and implicitly unlocks at method exit or on exceptions. ReentrantLock allows non-block locking sequences across multiple functions and offers interruptible acquisition via lockInterruptibly().

balance 2. Fairness Policy

synchronized cannot guarantee thread scheduling fairness. ReentrantLock can optionally instantiate a fair policy (new ReentrantLock(true)) ensuring longest-waiting threads gain access first.

timer 3. Polling & Timers

tryLock() enables timeouts to avert indefinite deadlocks, an operation natively impossible in standard monitor synchronization.

tips_and_updates
Key Takeaway Default to synchronized for simplicity; employ ReentrantLock when needing try-lock timeouts, fairness guarantees, or explicit interrupt handling.
